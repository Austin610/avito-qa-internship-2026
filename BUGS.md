### Наблюдения, требующие уточнения

Не включены в число подтверждённых дефектов:

- В карточке продавца статус «На проверке», в карточке товара — «Опубликовано». Нет подтверждения одинакового момента снятия скриншотов и правил статусов.
- У продавца имя «Гедеоныч», у покупателя — «Пользователь». В форме имя не задано; возможны правила отображения для неавторизованного посетителя.
- В статистике продавца 8 просмотров при пустом графике, в карточке товара 0. Требуются правила агрегации, задержки обновления и фактический момент снимков.
- В форме задан цвет производителя «Графит», в карточках его нет; обязательность отображения не описана. «Особенности» в карточках отсутствуют в форме, но могут вычисляться из других данных.
- Повторяющиеся элементы навигации внизу изображений могут быть артефактом получения длинного скриншота; без работающего UI это не доказанный дефект вёрстки.

## Задание 2.1 — API

### API01 — нулевой счётчик likes ошибочно считается отсутствующим

- Приоритет / серьёзность: P2 / Major.
- Окружение: `https://qa-internship.avito.com`, Python 3.14.6, Windows, 05.09.2026.
- Предусловия: зарегистрировать уникального пользователя через POST `/api/1/register`, получить токен через POST `/api/1/autorize`.
- Шаги: отправить POST `/api/1/item` с Authorization Bearer собственного пользователя, его sellerID, уникальным name, price=9900, statistics={"likes":0,"viewCount":0,"contacts":0}.
- Фактически: HTTP 400, ответ `{"result":{"message":"поле likes обязательно","messages":{}},"status":"400"}`. Поле likes передано явно, но трактуется как отсутствующее.
- Ожидается: HTTP 200 и UUID нового объявления; statistics сохраняет нули. Ноль — естественное начальное значение счётчика нового объявления; требование строго положительных счётчиков в задании отсутствует. Если продукт намеренно запрещает нулевые значения, это необходимо явно закрепить в контракте, а сообщение должно описывать ограничение значения, а не отсутствие поля.
- Автотест: `test_TC20_zero_statistics`, кейс TC20. Падает на создании, до запросов статистики. Поэтому этим результатом не доказаны дефекты GET statistics.
- Подтверждение: HTTP 400 повторился в полном прогоне и двух отдельных проверках; текст ответа получен в отдельной проверке. Токены и пароли не сохранены.
