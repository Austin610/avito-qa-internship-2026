## Запуск

Нужны Python 3.10+ и доступ в интернет. Сторонних зависимостей нет: установка через pip не требуется.

```sh
python -m unittest -v
```

Команда запускается из корня репозитория. В Windows при необходимости замените `python` на `py -3`.
Проверенный интерпретатор: Python 3.14.6, Windows. Код возврата 0 означает успешный прогон, 1 — ошибки или дефекты; падения не скрываются через skip/expectedFailure.

Запуск отдельного сценария:

```sh
python -m unittest -v test_api.ApiTests.test_TC21_e2e
```

По умолчанию используется `https://qa-internship.avito.com`, таймаут каждого запроса — 20 секунд. Необязательные переменные окружения:

```powershell
$env:BASE_URL = 'https://qa-internship.avito.com'
$env:API_TIMEOUT = '20'
python -m unittest -v
```

В Linux/macOS: `BASE_URL=https://qa-internship.avito.com API_TIMEOUT=20 python -m unittest -v`.

## Изоляция и очистка

Имя тестового пользователя для ручной демонстрации — "Austin61", id — "21612". Регистрация и вход проверены; пароль сохранён в зашифрованном локальном хранилище вне репозитория. Для повторного входа используется `/api/1/autorize`; повторная регистрация этого имени вернёт 409.

Каждый тест создаёт собственный экземпляр клиента. Если нужна учётная запись, регистрируется уникальный `student_<UUID>` с новым случайным паролем. Тесты не используют чужие объявления и не зависят от порядка запуска. Для защищённых запросов токен получается через `/api/1/autorize` (именно такое написание в контракте).

Объявления регистрируются для очистки сразу после получения UUID. `addCleanup` удаляет их и при падении assert; неуспешная очистка отдельно отображается как ошибка. При транспортном сбое только очистка повторяет идемпотентный DELETE один раз; HTTP-ошибки и проверяемые операции не повторяются. Удаление уже удалённого объявления с 404 допускается только при очистке. Тест повторного удаления отдельно ожидает 404.

Удаление пользователей API не предоставляет: созданные тестовые учётные записи остаются на стенде. Прерывание процесса или потеря сети могут помешать очистке объявлений. Пароли и токены существуют только в памяти; содержимое ответов авторизации не включается в отчёт.

## Интерпретация результатов

Проверки связаны с кейсами по `TCxx` в имени. Падение содержит ожидаемое и фактическое значение. API-дефекты в `BUGS.md` ссылаются на соответствующие тесты. Сетевой сбой/таймаут — проблема окружения, а не автоматически дефект продукта.

Ожидания основаны на задании и примерах Postman; неизвестные ограничения не выдумываются. Особенности неполного контракта и неавтоматизированные проверки указаны в `TESTCASES.md`. Не проводились нагрузочные проверки общего стенда. Дополнительно реализован E2E-сценарий; Allure, линтер и форматтер не добавлены.
